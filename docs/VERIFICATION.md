# Verification record

The initial build was checked on Linux with GCC and WASI SDK 25 (Clang 19), Python 3.12, and Node 22.

## Automated checks

- Native behavioral tests: stationary jump's exact initial trajectory and 242-unit peak; release-height reduction; button-edge behavior; stick deadzone/nonlinearity; walking acceleration and speed oscillation; double/triple jump chain; long jump; backflip; turnaround side somersault; speed-dependent dive/kick; ground pound; wall collision/kick; replay determinism; invalid input/geometry rejection.
- Native/WASM parity: all **80 bytes of the public state**, compared on **every frame of 360-frame input streams in each of six areas** (2,160 ticks). The stream includes walking, directional changes, jumps, crouching and attacks.
- Frame scheduling: identical 300-tick end state at simulated 30, 60 and 144 display frames per second.
- Level checks: all six destination spawns settle on the floor generated by their visible triangles.
- Pause clock clearing and long-stall catch-up limit.

Commands are in the README. The cross-compiler test runs the same inputs through the actual native shared library and committed WASM, not a JavaScript rewrite of physics.

## Practical limits

The connected browser in the development environment rejected local HTTP previews with `ERR_BLOCKED_BY_CLIENT`. The C and WASM execution tests ran, but a visual/browser-interaction QA pass could not be completed in that environment. Browser rendering, touch hardware, and physical gamepads therefore still need a hands-on pass. CI tests the simulation and distributes the static demo for that review.

These tests establish internal consistency and specific upstream behaviors. They do not establish N64 equivalence: no reference console/emulator trace was available. See [FIDELITY.md](FIDELITY.md) before using the word “exact.”
